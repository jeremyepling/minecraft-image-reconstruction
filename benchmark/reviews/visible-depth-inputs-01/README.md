# Frozen visible placement inputs

The release fixes the input photograph, metric camera, Surface Finder output and Block Counter output while placement methods choose visible cells. The upstream production revision is `651ef4f`. The input archive contains the 72 training, 12 validation, 12 test and 56 regression frames from Visible Builds v1. A further 12 native screenshots have supported cameras on six exterior layouts. The native group was screened for camera support before these experiments. RGB hashes are distinct across these cohorts.

The predictor receives one RGB image, game version, surface list, count report and image-estimated camera. Surface evidence and camera estimates come from that single image. Metadata in the cache identifies fixtures for the runner. Scoring opens recorded poses and block readbacks after the method produces a datapack and the runner decodes it. The decoded geometry uses smooth stone. Exact material-and-position matches count only where the target actually uses that ID.

For every proposed coordinate, the evaluator compares the registered world cell against the target cells visible from this image. Every other placement counts as an extra. The hidden subset overlaps an occupied building cell that lacks a visible face in the image. The scorer reports correct cells gained/lost and extras added/removed relative to the same baseline, including swaps whose aggregate count is unchanged. It weights each block appearance equally for pooled precision, recall and F1 and reports counts by family.

## Replay from the frozen inputs

Extract `inputs.zip` into `runs/visible-depth-rounds`. Each `inputs/FRAME.json` contains the frozen image-derived signals. Rendered sample crop names in these inputs are provenance. The placement predictor samples the original RGB.

Download and extract the [Visible Builds v1 dataset](../../../training/DATASET.md). The default layout is `runs/visible-builds-v1` with its versioned shards and extracted images and labels in `data`. Score the ordinary decoder first. A challenger implements `predict(image, version, parts, counts, camera)` and returns local coordinates or a pair containing those coordinates and diagnostics.

```powershell
python -m benchmark.visible_depth_score --split all --out runs/visible-depth-rounds/baseline
python -m benchmark.visible_depth_score --split train --candidate-root PATH_TO_CHECKOUT --candidate MODULE --out runs/MY_METHOD
```

For the independent native screen, use `--split native --native-fixtures PATH_TO_NATIVE_FIXTURES` on both runs. The native fixture root contains the saved capture directories named by `native-inputs/index.json` in the [earlier scoring archive](../texture-camera-01/scoring.zip). The baseline verifies each native world-coordinate set against the [earlier decoded result](../combined-default-01/evidence.zip). The 80 validation, test and regression outputs are each compared with their earlier registered coordinates, including empty builds.

For the simple grounded-chart-only control, pass `--candidate benchmark.visible_depth_score:strict_only`. Each method uses its own output directory. The archive `scores.zip` contains the round's baseline and control outputs, decoded coordinates, packs, scores and SHA256 manifests.

## Regenerate the upstream inputs

The 72 training surface/count reports were generated by running the ordinary `Invoke-WallRecovery.ps1 -Through counts` on each original RGB. The 80 held and regression frames reuse the frozen mask source from the preceding placement round; counting is rerun on those exact masks. The native input builder reuses the hash-checked `seam-review/promoted-inputs` masks on this PC. The camera matrices come from the saved image-only atlas-floor camera evaluation. To rebuild in a private output directory on this PC:

```powershell
python -m benchmark.visible_depth_inputs --split all --cache runs/my-frozen-inputs --build-train
python -m benchmark.visible_depth_native --cache runs/my-frozen-inputs
```
